**LTE Basic Rubric Model**

Starter Guide for Artifact-Based AI Evaluation

| **Start small: one artifact, five criteria, four scoring levels, critical failures and one clear decision rule.** |
|-------------------------------------------------------------------------------------------------------------------|

Purpose: Enable course teams to begin building consistent rubrics in LTE
without using the full advanced architecture at the start.

# 1. Why a Basic Version Is Needed

LTE will use AI to evaluate learner-created workplace artifacts. The
first version of the rubric system should therefore be simple enough for
course teams to create, test and improve without managing a large number
of layers or rules.

| **Do now**                               | **Add later**                             |
|------------------------------------------|-------------------------------------------|
| Define the artifact and expected outcome | Full L1-L5 progression logic              |
| Use four to five observable criteria     | Cross-industry capability libraries       |
| Use a four-level scoring scale           | Employer-facing proficiency signals       |
| Add a few critical failure checks        | Advanced confidence and moderation models |
| Use simple pass / revise / review logic  | Complex portfolio weighting               |

# 2. Basic LTE Rubric Structure

Each artifact rubric should contain only four parts.

**1. Artifact purpose** - State what the learner must produce and what
the artifact should achieve.

**2. Assessment criteria** - Use four to five observable criteria that
can be checked directly in the submitted artifact.

**3. Performance scale** - Use the same four scoring levels across LTE.

**4. Critical failures** - List the few non-negotiable errors that
require correction or human review.

# 3. Standard Assessment Criteria

The following five criteria can be used as the default starting point
for most artifacts. Teams may rename or replace a criterion when the
artifact requires a different form of evidence.

| **Criterion** | **What AI checks**                                               | **Typical evidence**                                      |
|---------------|------------------------------------------------------------------|-----------------------------------------------------------|
| Completeness  | All required sections, fields or outputs are present.            | Required fields, attachments, sections or entries         |
| Accuracy      | The content matches the supplied case evidence and instructions. | Correct facts, values, references and status              |
| Evidence use  | Sources or case evidence are correctly identified and used.      | Reference IDs, version numbers, source links or citations |
| Judgement     | The learner identifies gaps, risks, mismatches or uncertainty.   | Observed issue, reasoning, exception or risk statement    |
| Next action   | The recommended action is appropriate for the learner role.      | Recommendation, escalation, owner or follow-up step       |

# 4. Standard Four-Level Scale

| **Score** | **Level**              | **Meaning**                                                     |
|-----------|------------------------|-----------------------------------------------------------------|
| 0         | Not demonstrated       | No valid evidence, missing response or fundamentally incorrect. |
| 1         | Partially demonstrated | Some correct elements are present, but important gaps remain.   |
| 2         | Demonstrated           | Meets the expected task and level requirements.                 |
| 3         | Strongly demonstrated  | Accurate, complete and usable with clear judgement.             |

Recommended starting rule: essential criteria must score at least 2. A
high score in one area should not compensate for failure in an essential
criterion.

# 5. Critical Failure Checks

Critical failures are not normal scoring criteria. They are
non-negotiable errors that require revision or human review.

- Fabricated or invented evidence

- Unsupported confirmation presented as fact

- Unsafe or prohibited recommendation

- Action outside the learner role or authority

| **Important: A critical failure should not be balanced against the total score. The submission should move to revise and resubmit, or to human review when the case is unclear.** |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 6. Basic AI Evaluation Flow

The AI should evaluate the artifact in three simple stages.

**Stage 1 - Submission check**

- Correct artifact submitted

- Required sections are present

- Content is readable and assessable

**Stage 2 - Critical failure check**

- No fabricated information

- No unsupported confirmation

- No unsafe or prohibited action

**Stage 3 - Criterion scoring**

- Score each criterion from 0 to 3

- Identify evidence from the artifact

- Give one clear improvement point

# 7. LTE Decision Rule

| **Result**          | **When it is used**                                                                                  |
|---------------------|------------------------------------------------------------------------------------------------------|
| Pass                | No critical failure and every essential criterion scores at least 2.                                 |
| Revise and resubmit | One or more essential criteria score below 2, or a correctable critical failure is found.            |
| Human review        | AI confidence is low, evidence is unclear, or the case has safety, regulatory or unusual complexity. |

# 9. How the Team Should Start

1.  Select one course and one learner artifact.

2.  Define the artifact purpose in one sentence.

3.  Choose four or five criteria from the standard set.

4.  Add only the critical failures relevant to that artifact.

5.  Test the rubric against three sample submissions: weak, acceptable
    and strong.

6.  Compare AI scores with a human reviewer and correct unclear
    criteria.

7.  Approve the rubric for a small pilot before scaling to more courses.

# 10. Working Principles

- The rubric should assess the learner artifact, not the course content
  in general.

- Every criterion must be observable in the artifact or its supplied
  evidence.

- AI must explain each score using evidence from the submission.

- The first version should remain simple and consistent across the
  pilot.

- Advanced layers should be added only after the basic model is stable.
